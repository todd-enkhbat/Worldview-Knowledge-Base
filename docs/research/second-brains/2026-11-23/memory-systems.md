**The important correction to the viral framing:** these are systems for building a memory, not downloads of their authors' private knowledge. GBrain's repository supplies an engine, integrations, examples and operating workflows. Its own README describes creating a separate private personal-agent repository. It does not distribute Garry Tan's complete private notes, conversations or personal corpus. Basic Memory is a knowledge server around files. Supermemory's public repository currently supplies applications, integrations, graph UI and documentation; cloning it does not provide the proprietary extraction and graph engine. [GBrain setup and architecture](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/README.md), [Supermemory local boundary](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/docs/self-hosting/local-vs-enterprise.mdx).

## GBrain: a shared memory authority with provenance, policy and upkeep

**What makes it stand out.** Its most useful contribution is a complete lifecycle around remembered claims: who asserted one, what source and subject it belongs to, what superseded it, when it was considered valid, how trusted its origin is, and whether its old history is still readable under today's access policy. It also treats cross-agent access as an explicit protocol and persistence problem. This is much more than adding vector search to a folder.

**How the memory is built.** Pages are grouped into sources within a brain. File-backed knowledge is represented in Markdown/frontmatter, with structured facts, takes, links and timeline material. PostgreSQL or embedded PGLite supplies queryable projections, vectors and operational state. A shared operation registry serves CLI and MCP. Ingestion and optional enrichment produce claims and relationships; recurring maintenance can reconcile, link, deduplicate and propose changes. Explicit remembering and keyword retrieval work without an extraction model. The always-on enrichment workflow is a separately configured service, not an intrinsic consequence of cloning the repository. [Architecture and lifecycle](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/README.md), [system of record](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/docs/architecture/system-of-record.md).

**The source-of-truth boundary is nuanced.** Markdown reconstructs represented file-backed knowledge, but does not reconstruct everything in the database. Unresolved/database-only facts, mutation receipts, historical editions, withdrawal decisions, credentials and the belief ledger require a database backup. The code coordinates publication rather than assuming a file write and database transaction are one atomic action. Its documentation describes durable request identities, optimistic revisions, designated publishing ownership, recovery records, committed receipts, and separate retryable Git/embedding effects. This is directly relevant before Worldview adds two-way Markdown editing or shared agent writes. [Persistence contract](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/docs/architecture/system-of-record.md).

**Verified implementation details:**

- `FactRow` carries source identity, entity, claim kind, visibility, validity interval, expiry, supersession, textual provenance, session, confidence and optional attributed speaker/trust fields. Attributed speaker distinguishes user, assistant and other; unknown remains possible. A required `source` string is attribution, not by itself a cryptographically authenticated passage citation. Worldview's retained version IDs and exact source offsets should remain the stronger evidence anchor. [Fact contract](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/engine.ts#L620).
- The belief ledger records events, source incarnation, page lifetime, publication ID, recorded/source/valid times, prior/state hashes, cause and redaction state. Its purge epoch prevents a prepared old output from being published after a purge. This is a concrete pattern for “how did my view change?” beyond simply replaying record births in 3D. [Belief schema](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/belief/schema.ts).
- Historical reads apply current visibility as well as event-time visibility. A now-private page or claim hides earlier public events; deleted lifetimes and private link endpoints also restrict history. This prevents a history view from bypassing a later privacy decision. [History reader](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/belief/history.ts).
- Forgetting first records a durable withdrawal. It then updates a Markdown fence where possible. Reimporting stale source text cannot silently reactivate the same normalized withdrawn claim. This is retraction, not a promise to erase every original or exported backup. [Forget implementation](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/facts/forget.ts), [withdrawal implementation](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/facts/withdrawal.ts).
- Trust is explicit: confirmed user input, curated notes, tool observations, agent output, unknown origin and untrusted external input are different tiers. Relaying the user's words does not automatically promote an agent-written record into a user-confirmed fact. [Trust vocabulary and rules](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/trust/tier.ts).
- Generated summaries can be demoted when primary evidence about the same entity is present. Corrections are exempted from that particular demotion. This avoids retrieving a synthesis of a synthesis while obscuring the actual record. [Provenance-aware ranking](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/search/provenance-demotion.ts).
- Evidence delivery expands a hit to neighboring chunks, a section or a page, reauthorizes the stored body before slicing, supplies revision/span information, and reports truncation and budget omissions. Retrieval and context assembly are separate stages. Its explicit budgets and fallback reasons are more useful to Worldview than copying an arbitrary large context window. [Evidence delivery](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/search/evidence-delivery.ts), [budget policy](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/search/evidence-packing.ts).
- Fusion aggregates agreement at page grain while retaining chunk evidence and source identity. This addresses an important failure mode: keyword and vector search can select different chunks from the same relevant document. [Page-grain RRF](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/search/rrf-page-fusion.ts).

**What not to copy blindly.** The single-fact helper documents similarity-based supersession: sufficiently similar, same-kind, different text can be treated as an update. Similarity does not prove that two claims concern the same subject, time or proposition; Worldview should initially propose such a replacement for review. Its own comment notes sequential dedup can admit duplicates under racing submissions on that seam. The decay module's “half-life” constants are used in `exp(-age / constant)`, which yields about 36.8%, not 50%, at the named interval. More fundamentally, aging usefulness must not be equated with a fact becoming false. Its trust floor and explicitly dated historical-fact exception are useful cautions. [Single-fact write](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/facts/write-single.ts), [decay math](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/src/core/facts/decay.ts).

**Stack fit.** The repository declares Bun >=1.4.4 and uses PostgreSQL/PGLite, pgvector and a large engine contract. It is not a drop-in replacement for Worldview's Node 26, `node:sqlite`, SQLite FTS5 and existing store adapters. Pure functions are much easier to reuse than persistence or MCP entrypoints. There is no reason to replace Worldview's renderer or integer physics to obtain its memory concepts. The root MIT notice permits reuse subject to its terms; vendored Node/PostgreSQL/Snowball/company-example material has separate license/notice files. [Package contract](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/package.json), [MIT license](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/LICENSE).

**Maturity evidence, without claiming execution.** The checked-out package identifies itself as `0.60.765.0` on `master`. The README distinguishes stable from rapid releases and describes substantial load qualification, but that qualification was not reproduced here. Relevant reviewed tests include private-to-public and public-to-private history transitions, re-added source incarnations, private link endpoints, retained/pruned editions, and withdrawal races. These are valuable test-design references, not proof that importing GBrain into our stack would work. [History/privacy tests](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/test/belief-ledger-privacy.test.ts), [valid-time tests](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/test/valid-time-gbra217.test.ts), [withdrawal/recovery tests](https://github.com/garrytan/gbrain/blob/47512aa50fa2be1ab3af55bf60c242a11be76392/test/managed-facts-withdrawal-recovery-6506.test.ts).

## Basic Memory: editable Markdown with a structured, queryable graph

**What makes it stand out.** It gives ordinary notes a useful lightweight grammar: typed observations, named relations and links, optional schemas, and stable addresses. An agent can retrieve and update the same knowledge the person opens in an editor. It does not require every note to become a model-generated summary or a rigid database form.

**How it is built.** A Python service parses Markdown/frontmatter and projects entities, observations, relations, sections and search rows into SQLite or PostgreSQL. MCP tools provide note CRUD, graph context, search, project selection and recent activity. Watch/index/reconciliation workflows observe external edits. Semantic retrieval and optional reranking are separate adapters. Current code is considerably more sophisticated than the original “a few Markdown files exposed to Claude” description. [Note grammar](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/NOTE-FORMAT.md), [graph models](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/models/knowledge.py), [MCP tool implementation](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/mcp/tools/write.py).

**Verified implementation details:**

- Entity UUIDs are stable API identities while database-generated integers serve relational joins. Project-scoped path/permalink constraints and normalized path conflict keys avoid treating filenames alone as identity. This reinforces Worldview's existing source IDs and full-path imports rather than replacing them with titles. [Entity model](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/models/knowledge.py#L53).
- A note owns categorized observations and directed, named relations. Deleting a relation target sets the target reference to null while preserving its unresolved name; it does not pretend a broken outgoing link no longer exists. Relation generations bind the projection to the accepted note revision. [Relation model](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/models/knowledge.py#L652).
- The current accepted-note path contains `NoteContent`: Markdown bytes, database version/checksum, file version/checksum and pending/writing/synced/failed/external-change state. Canonical Markdown is a product representation; current writes are coordinated through accepted state before materialization in some flows. It would be inaccurate to describe every runtime as “the database is always disposable.” The architecture explicitly distinguishes local durable files from accepted materialization. [Content state](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/models/knowledge.py#L242), [engineering contract](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/docs/ENGINEERING_STYLE.md), [mutation service](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/services/note_content_writes.py).
- Existing-note replacement can require an `expected_checksum` returned by reading the note. Separate created, updated, moved, locked and revision-conflict outcomes let the agent respond to the actual state rather than repeatedly overwriting. Authorship stamps are resolved at a trusted boundary, not accepted from arbitrary route arguments. [Write tool](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/mcp/tools/write.py), [mutation actor handling](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/services/note_content_writes.py).
- Semantic chunks have content identity independent of transient search-row IDs, with an occurrence index for repeated identical text. The inspected planner uses 900-character chunks and 120-character overlap, preferring structure before character windows. Moving unchanged material within a note can reuse embeddings while locations are updated. This can reduce Worldview's re-embedding work after small edits; the particular limits need our own evaluation. [Chunk planner](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/repository/semantic_chunking.py), [identity and structural chunk tests](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/tests/repository/test_semantic_chunking.py).
- SQLite FTS5 and SQLite vector adapters are first-class, with provider identity/freshness checks and optional cross-encoder reranking. This is close to our architecture, although the implementation is Python/SQLAlchemy rather than our TypeScript store layer. [SQLite search](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/repository/sqlite_search_repository.py), [retrieval reader](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/repository/search_reader.py).
- Context traversal takes explicit depth, pagination and scope; its code distinguishes local cross-project traversal from hosts where project readers differ. Bounded graph expansion is a useful future tool for Worldview's question-centered exploration, but must remain constrained by our per-source AI policy. [Context service](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/services/context_service.py), [context tool](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/mcp/tools/context.py).
- Temporal observations distinguish when a statement applies from when a file changed. The parser refuses relative/ambiguous forms rather than swallowing adjacent prose into a plausible date; failed qualifiers remain searchable original text. This is useful for future valid-time claims alongside Worldview's authored/capture dates and spatial history. [Temporal qualifier parser](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/markdown/temporal_qualifier.py), [temporal projection model](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/src/basic_memory/models/knowledge.py#L550).

**License and integration consequence.** `pyproject.toml` declares Python >=3.12 and AGPL-3.0-or-later, and the actual root license is AGPLv3. Do not treat current core code as permissively licensed because an older article says otherwise. Before combining copied core code with Worldview, explicitly resolve the resulting license obligations or obtain another license. We can study the design and independently implement an interoperable Markdown format. The separately licensed MIT OpenClaw integration is a more limited reuse candidate, not a license exception for its upstream Python server. [Declared license and dependencies](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/pyproject.toml), [core license](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/LICENSE), [OpenClaw license](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/integrations/openclaw/LICENSE), [Hermes license](https://github.com/basicmachines-co/basic-memory/blob/506305b856967da1799f530502b6d9b7e6bd9610/integrations/hermes/LICENSE).

## Supermemory: a useful context API, with an important public-source boundary

**What makes it stand out.** It separates raw documents from atomic extracted memories, distinguishes persistent profile material from recent context, and exposes a consistent namespace-scoped API to different agent clients. Update/extend/derive relationships give the graph semantic meaning. Its public graph UI includes lineage inspection rather than just floating points.

**What is actually present in the download.** The public monorepo contains the web application, MCP application, documentation, integration packages, and the `@supermemory/memory-graph` React package. The inspected MCP client delegates extraction, memory retrieval and profiles to an API. This repository is useful integration source, but is not a freely reusable implementation of all the advertised engine internals. [Client implementation](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/mcp/src/server/client/index.ts), [public graph package](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/packages/memory-graph/package.json).

**Verified implementation versus service claims:**

- API-facing types and graph UI distinguish `updates`, `extends` and `derives`, with latest/forgotten flags and parent/root memory IDs. The version-chain implementation walks those relationships for presentation. That verifies a public contract and visualization, not the proprietary model's reasoning or extraction accuracy. [Graph types](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/packages/memory-graph/src/api-types.ts), [version-chain implementation](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/packages/memory-graph/src/canvas/version-chain.ts), [conceptual graph description](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/docs/concepts/graph-memory.mdx).
- MCP search returns memory IDs and available source-document IDs; a separate read fetches original document context. Profiles expose stable and dynamic arrays. The current tool deliberately keeps searching and profile retrieval separate, so an agent need not receive a full user profile on every lookup. [Search tool](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/mcp/src/server/tools/search-memory.ts), [client mapping and profile behavior](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/mcp/src/server/client/index.ts).
- Forget-by-text returns candidates when there is no exact match, instead of deleting the closest semantic neighbor. Explicit IDs target the subsequent mutation. The client disables automatic retries for committed forgetting to avoid turning a successful mutation into a misleading not-found response. These are useful mutation UX and idempotency lessons. [Forget tool](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/mcp/src/server/tools/forget-memory.ts), [API client](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/mcp/src/server/client/index.ts).
- MCP tool metadata explicitly distinguishes read-only, additive and destructive operations. Namespace/session permissions are propagated into choices in its UI. Hints aid client presentation; actual authorization still belongs on the server and cannot be replaced by an annotation. [Annotations](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/mcp/src/server/tools/annotations.ts), [RBAC mapping](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/mcp/src/server/auth/rbac.ts), [RBAC tests](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/mcp/src/server/auth/rbac.test.ts).
- The local-vs-enterprise documentation explicitly states that server source is not in the public repository and describes a lite limit of 10,000 stored documents. Local text processing can use local models after initial downloads; webpage ingestion still requires Firecrawl, and continuous hosted connectors are not part of the local feature column. A source clone therefore cannot establish a completely open, unlimited, offline stack. [Local limits and engine boundary](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/apps/docs/self-hosting/local-vs-enterprise.mdx).
- `@supermemory/memory-graph` declares React >=18 peers and `d3-force`. Its canvas version/history and edge semantics are useful references for a small relationship inspector. Installing it to replace Worldview's 3D world would introduce another force simulation and compete with the stable shared XYZ contract. Prefer its interaction concepts or isolated MIT utilities if they survive adaptation. [Package dependencies](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/packages/memory-graph/package.json).

**License consequence.** The public root is MIT, but the bundled `skills/supermemory` has an Apache-2.0 license. Preserve the relevant notices for any actual copied component. Neither license grants source access or redistribution rights for a different proprietary binary merely mentioned by the README. [Root license](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/LICENSE), [skill license](https://github.com/supermemoryai/supermemory/blob/fa2af930dd78ba5504d7f35875d57f62084fdb5a/skills/supermemory/LICENSE).

## Concrete value for Worldview

The scores below are engineering judgments for our current project, not upstream benchmark results. Value is 1–5; effort describes adapting the idea within our authority, permissions and retained-original model.

| Candidate | Value | Reuse route | Worldview landing point and acceptance check |
|---|---:|---|---|
| GBrain claim/event ledger, including current-policy historical reads | 5 | Implement SQLite-native model from the design; do not port the entire engine. | Extend `src/knowledge/types.ts` additively with assertion revisions and evidence IDs; normalize server storage. Verify an update preserves old evidence, explicit temporal validity and current visibility. |
| GBrain durable claim withdrawal and purge epoch | 5 | Adapt semantics and tests; claims are distinct from deleting source originals. | Knowledge commands + background jobs. Forget a claim, replay stale input, and verify it remains withdrawn; an old job cannot republish after purge. |
| GBrain evidence assembly and page-aware fusion | 5 | MIT algorithms can be extracted with attribution, but current module imports require adaptation. | `server/knowledgeIndex.ts`, `src/ai/corpusSemantic.ts`, `src/ai/chat/apply.ts`. Keyword/vector hits in different passages of the same document should agree without crowding other sources; context never exceeds budget or crosses policy. |
| GBrain `supersededValidUntil` pure helper | 3 | Closest direct-copy candidate: zero imports and erasable TypeScript, MIT. Still validate dates and fit our semantics before using. | Future assertion validity module. Cases: backdated replacement, future replacement, earlier explicit expiry, zero-length intervals. |
| Basic Memory structured observations/relations and optional schema notes | 5 | Independently implement compatible grammar; core copying requires an explicit AGPL decision. | Retained note parsing + optional app-managed Markdown export. Preserve literal wording, unknown types and unresolved links; semantic type must not replace render archetype. |
| Basic Memory content-stable chunk/embedding identity | 5 | Independently implement the identity strategy; do not copy AGPL planner by default. | `src/knowledge/parsers.ts`, `src/ai/corpusSemantic.ts`. Reordering unchanged sections reuses vectors while citations still point to the correct retained version/offset. |
| Basic Memory checksum-bound file materialization | 4 | Design reference for eventual two-way vault writes. | Current `server/folderCapture.ts` remains one-way until conflicts, recovery receipts and external edits are specified. Never silently overwrite an edited vault file. |
| Supermemory namespace-scoped profile packets | 4 | Independently implement an evidence-backed packet contract; optionally add a provider adapter later. | Current chat evidence assembly. Profile material must identify scope, provenance, source policy and freshness; stable preferences and recent activity remain distinct. |
| Supermemory graph lineage and exact-ID forgetting UX | 4 | MIT UI/utility reuse possible after compatibility review. | Reader/Review/Explore inspector. Show update/extension/inference distinctions and original evidence; never infer deletion targets from nearest-neighbor search alone. |
| Full GBrain sidecar or Supermemory service replacement | 2 | Optional controlled experiment, not the default architecture. | Import a synthetic fixture into an isolated service and benchmark it against our own retrieval. No personal source upload, automatic account linking or authority switch during this research. |

Worldview already has retained originals and source versions, exact-offset passages, source/AI permissions, SQLite FTS, optional passage vectors, lexical proposal review, saved investigations, local watched-folder capture and backup recovery. Those should not be discarded. Its main gaps relative to these projects are a normalized incremental corpus authority, explicit claim/revision/withdrawal semantics, an external read-only agent interface, token-budgeted context assembly with retrieval explanations, and interoperable editable knowledge exports. Relevant local implementation: [types](/Users/kintekente-mac/Documents/GitHub/Worldview-Knowledge-Base/src/knowledge/types.ts), [knowledge commands](/Users/kintekente-mac/Documents/GitHub/Worldview-Knowledge-Base/src/knowledge/index.ts), [FTS index](/Users/kintekente-mac/Documents/GitHub/Worldview-Knowledge-Base/server/knowledgeIndex.ts), [passage vectors and fusion](/Users/kintekente-mac/Documents/GitHub/Worldview-Knowledge-Base/src/ai/corpusSemantic.ts), [review candidate index](/Users/kintekente-mac/Documents/GitHub/Worldview-Knowledge-Base/src/knowledge/organization.ts).

**Recommended order:** normalize and incrementally write source/passages first; expose narrow policy-checked search/read/citation tools; add evidence-linked assertions with review and durable withdrawal; then Markdown export/materialization and richer maintenance. Evaluate improved fusion, context windows and reranking against a frozen corpus before changing defaults. Keep primary evidence and interpretation separate. A shared memory authority is the goal; running several incompatible authorities with automatic bidirectional writes would multiply the very context and recovery failures we just fixed.
