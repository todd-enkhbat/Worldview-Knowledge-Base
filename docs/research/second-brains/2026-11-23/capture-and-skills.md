## 1. claude-mem: remember what an agent learned, then disclose it progressively

### How the system is built

The hook manifest wires session start, prompt submission, successful and failed tool use, pre-tool file context, stop, subagent stop and session end into a normalized command interface. This is lifecycle integration rather than asking a chatbot to remember. [Hook manifest](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/plugin/hooks/hooks.json).

The observation handler normalizes the platform, requires the working directory, honors project/tool/subagent exclusions, prevents recursive memory-tool observations, bounds inputs, and routes to a local worker or server. Explicit memory writes are treated differently from ordinary tool output so they do not generate another observation of the same note. A short server-attempt timeout on the Codex path protects the host hook deadline. [Observation dispatch](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/cli/handlers/observation.ts#L32).

There are two important persistence paths:

- The **local worker bridge** deliberately treats observation, file-edit and summary inference inputs as disposable live messages. They have a five-minute age limit, 128 messages per session and 1,024 total. Its durable spool now handles metadata such as session ends, deliverables and work-state events. Atomic per-event files, deterministic identities and consumed receipts prevent duplicate metadata handoffs. An unavailable observer therefore must not be equated with a guaranteed raw-input archive. [Live policy](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/shared/observer-work-policy.ts#L1), [spool contract](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/shared/hook-spool.ts#L14), [handoff](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/cli/spool-hook-event.ts#L224).
- The **server generation path** has canonical event/job records. A parsed provider response is committed with observation rows, source links, usage/audit data and a job transition in one Postgres transaction. Generation keys and unique source links collapse retry duplicates; stale processing attempts cannot claim a newer attempt. This is useful outbox/job design, distinct from the local bridge's ephemeral inference buffer. [Generation completion](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/server/generation/processGeneratedResponse.ts#L26).

Generated memory is structured: type, title, subtitle, narrative, facts, concepts and files read/modified. Platform and project attribution travel separately. Memory source records can point to underlying observations, summaries, prompts, manual entries or imports. These fields make operational recall inspectable, but a model-generated fact is still an interpretation; they are not a substitute for Worldview's human/assistant attribution and exact source-version evidence. [Memory schemas](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/core/schemas/memory-item.ts#L8), [XML parser](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/sdk/parser.ts#L236).

### What makes recall effective

Its strongest transferable interaction is **small index → local timeline → selected details**. The progressive search contract bounds candidate counts, timeline depth, details, title size and total response bytes. A prompt can be an index entry without qualifying as a fetched observation. The worker adapter rechecks a fetched row's project rather than authorizing arbitrary future content under an old ID. This resembles our search/read split, but adds an explicit neighborhood in time and a reusable structured context packet. [Progressive contract](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/shared/progressive-search.ts#L15), [worker adapter](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/services/worker/ProgressiveMemorySearch.ts#L23).

Automatic session context is rendered under an actual delivery budget. Large narratives go before summary/prior-message sections and finally older timeline items; a binary refinement recovers more entries after halving. The same selected memory renders compactly for the model and readably for the person. This is better than estimating context from a fixed number of arbitrary-length notes. The upstream 10,000-character constant is host-specific, not a value to adopt blindly for every Worldview provider. [Budget fitter](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/services/context/ContextBudget.ts#L82), [context assembly](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/services/context/ContextBuilder.ts#L160).

The hybrid file lookup demonstrates a practical boundary: metadata/date pages come from scoped SQLite; vector search ranks allowed candidates, then SQLite hydrates within the same project/platform scope. Date-ordered requests avoid an unnecessary semantic dependency. [Hybrid file search](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/services/worker/search/strategies/HybridSearchStrategy.ts#L22).

### Privacy, deletion and limits worth learning from

Balanced private/context/system tags are stripped with a scanner designed to avoid quadratic malformed-tag behavior. Explicitly private-empty prompts suppress observation generation, whereas a missing prompt record is treated as a race and permitted with a warning. That fail-open distinction is an upstream design decision; Worldview should continue to require explicit source eligibility and recheck it before enrichment, instead of treating unknown permission as permission. [Tag processing](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/utils/tag-stripping.ts#L8), [privacy validator](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/services/worker/validation/PrivacyCheckValidator.ts#L21).

Deletion accounts for replicas. An acknowledged synced entity cannot be silently deleted while its sync identity is unavailable. Successful deletion queues/commits the row removal, invalidates context and serializes background Chroma cleanup. This illustrates why adding encrypted/offline sync later needs tombstones and replica semantics, not merely a shared folder. Best-effort vector cleanup is not the same as an immediate physical-erasure guarantee. [Delete path](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/src/services/worker/http/routes/DataRoutes.ts#L498).

The root package expects Node and Bun, and the code uses bun:sqlite and non-erasable TypeScript constructs. The Postgres generation deployment also introduces Redis/BullMQ and authentication infrastructure; worker search integrates Chroma. The repository also contains a SQLite server path, so these are deployment choices rather than universal requirements. This is not a small drop-in replacement for our pinned Node SQLite stack. [Package/runtime](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/package.json#L76).

**Best use in Worldview:** retain our originals and source ledger; add opt-in agent-session adapters and a normalized, budgeted evidence packet. Reuse small pure algorithms or adapt them, rather than embedding its entire worker, cloud sync or installation machinery.

Tests inspected include privacy-before-storage/search/context, absent-vs-empty privacy, atomic tombstones, failed-delete no-broadcast and Chroma cleanup. This audit did not execute them. [SQLite privacy tests](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/tests/server/sqlite-memory-privacy.test.ts#L61), [delete tests](https://github.com/thedotmack/claude-mem/blob/29bc1cdf32aca60b3bfeec3b718d4ed6614b4f97/tests/worker/http/routes/data-routes-delete-sync.test.ts#L95).

## 2. agent-second-brain: a capture habit plus a maintained, typed vault

### The actual pipeline

The system is an aiogram Telegram bot on Python 3.12+, a Markdown vault, Deepgram speech transcription, persistent Claude Code terminal sessions, systemd supervision and file-based scheduling. It is a personal shared vault with an allowlist, not a tenant-isolated SaaS backend. The dispatcher defaults to denying access when no allowed IDs are configured, but an explicit allow-all setting exists. [Dependencies](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/pyproject.toml), [authorization](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/src/d_brain/bot/main.py#L53).

Text is appended to a dated Markdown safety log, then sent to the conversational agent. Media downloads are saved as attachments before interpretation; forwarded attribution is carried into the prompt, and albums are batched so multiple photos do not create repeated agent turns. Unsupported types and oversized Telegram downloads produce explicit replies instead of silent success. [Text/media handling](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/src/d_brain/bot/handlers/chat.py#L331), [attachment naming](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/src/d_brain/services/storage.py#L62).

Voice is a weaker durability path: downloaded bytes go to Deepgram first; only a successful transcript is saved to daily/session records. The handler does not persist the original voice bytes before transcription. Its service selects Nova-3 and hardcodes Russian. These are precise reasons to adapt the intake experience while keeping our original-first policy and configurable language. [Voice handler](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/src/d_brain/bot/handlers/chat.py#L280), [transcriber](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/src/d_brain/services/transcription.py#L20).

Its agent runs inside tmux. Cross-process flock, reply markers, prompt-state classification, liveness checks and owner-only runtime files make that workable, but replies still depend on changing terminal UI behavior. Startup uses skipped permissions and code actively accepts the corresponding prompt. We should not port that launcher, prompt acceptance, or subscription-billing workaround. Use supported provider/API boundaries and Worldview's command/policy layer for any connector. The advertised flat-subscription economics are upstream claims, not a verified cost/terms guarantee. [Terminal driver](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/src/d_brain/services/claude_session.py#L203).

### The memory system is mostly the vault protocol

The autograph subsystem adds schema-driven card types, status enums, domain inference, frontmatter normalization, deduplication proposals, backlinks, maps of content and resurfacing. Its useful separation is deterministic scripts for structural work and model judgment for classification/relationships. We should preserve that separation in our durable job/proposal model rather than letting an agent rewrite canonical sources freely. [Autograph workflow](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/vault/.claude/skills/autograph/SKILL.md), [example schema](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/vault/.claude/skills/autograph/schema.example.json).

An especially useful small algorithm is its wikilink resolver: exact path, unique suffix, unique stem, otherwise an explicit missing/ambiguous result. This is directly relevant to our legacy vault importer, which reduces references to basenames and stores one ID per name. Two folders containing Plan.md can currently create a silent last-wins link choice in that path. Port the resolution principle and add collision fixtures; do not copy the Python parser wholesale into our TypeScript project. [Link index/resolution](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/vault/.claude/skills/autograph/scripts/common.py#L311).

Deduplication can emit a review manifest with every cluster initially unapproved. Same stems with different headings, ontology layers or case collisions can be held apart. Approved merges consolidate content, redirect links and move extras to trash with logs. The candidate signal is not proof of identity; Worldview should keep independent provenance and show a preview/undo before source merges. [Dedup manifest](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/vault/.claude/skills/autograph/scripts/dedup.py#L182).

Its forgetting mechanism is an Ebbinghaus-inspired heuristic, not a validated cognitive model: linear relevance decline with a floor, slower rates after more accesses via 1 + ln(access_count), and separate age-based tiers. Core notes are protected. A useful adaptation is ranking/resurfacing without deleting or demoting evidence, while recording actual accesses as derived events. Do not change source-authored dates to simulate recall. [Relevance and tiers](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/vault/.claude/skills/autograph/scripts/common.py#L457), [touch/resurface](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/vault/.claude/skills/autograph/scripts/engine.py#L97).

Graph health reports broken links, orphans, descriptions and average link density. It subtracts a density penalty below three links per file. That is structural housekeeping, not an evidence-quality score; copying the target would encourage links merely to make a gauge green. Keep independent metrics and make every proposed relationship explainable. [Health calculation](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/vault/.claude/skills/autograph/scripts/graph.py#L78).

The scheduler persists next_run before invoking the model, isolates cron from conversational context, retries one-shots and disables repeated failures. Its comments call this at-most-once, but a crash after execution before successful completion can rearm a one-shot. External actions therefore still require idempotency keys; do not infer exactly-once delivery. [Claim/run path](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/src/d_brain/services/cron_runner.py#L76).

**Best use in Worldview:** capture-to-inbox UX, ambiguity-safe linking, manual duplicate-review manifests and gentle resurfacing. We already have local timestamped Whisper transcription, so adding Deepgram is optional rather than foundational. A Telegram adapter should be a separately scoped inlet to our existing corpus; it should not become another authority or expose the whole vault to a terminal agent.

Tests inspected cover session liveness, pane privacy, concurrent steering, media handling, next-run-before-execution, one-shot retries and crash survival. These were read, not run. [Session tests](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/tests/test_claude_session.py#L219), [cron tests](https://github.com/smixs/agent-second-brain/blob/7828ed62cf76aae87bee7f2660468ab88495cf3d/tests/test_cron_runner.py#L102).
