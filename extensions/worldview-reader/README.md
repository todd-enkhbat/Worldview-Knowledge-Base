# Worldview Reader

Load this directory as an unpacked Manifest V3 extension in Dia, Chrome or Edge. No build or dependency install is required. The downloaded ZIP contains the same files in its WorldviewReader folder. Version 0.4.1 keeps the existing active-tab, scripting, storage and local-service permissions; it adds no browsing-history or all-sites access.

1. Start the Worldview app locally at http://localhost:5173.
2. Open chrome://extensions (or edge://extensions), turn on Developer mode, click Load unpacked, and choose this folder.
3. Open the extension popup and click Connect to Worldview. In the local app’s Browser reader panel, approve the browser request you just made.
4. Reopen the extension popup to finish connecting automatically. No ID or token copying is needed. The token is saved only in this browser’s trusted extension storage; content scripts never receive it. Requests expire after five minutes; pairings last 90 days. The advanced token flow remains available as a fallback.
5. On an ordinary article page, explicitly choose Save and follow this article. A blue ON badge identifies the selected tab. Select text and reopen the popup to save it with an optional comment.

For actual profile data, choose **Save profile or company**. On a person's main LinkedIn profile, open/load Education, Experience and any affiliations first. On a company page, its visible header/About details can supply the company name, website, industry and location. The company People tab is supported, but employee school aggregates are kept only in the page source; they never become an individual's education or a company's alma mater. Main person profiles are required; a detached Education details page does not establish the person's identity.

The same action reads a primary, name-bound Person or Organization in a public site's JSON-LD. A generic personal page without schema needs a matching named portrait and explicit Education and Experience sections. Related people, hidden content, form values and unrelated schema entities are excluded. It does not guess graduation or fill sections that are private, collapsed or not loaded.

The loaded readable text and safe HTML structure are retained privately as a CRM source snapshot, alongside extracted values and their excerpts. This is a readable archive rather than a pixel-identical copy of a live website: scripts, forms, embeds, cookies and browser credentials are excluded. No cloud AI, paid enrichment or background crawl is used. **People opens a review before any contact or company is created or updated.** Existing records are matched by attached profile URLs, and the user chooses the fields and target. Reader reuses an existing local Worldview tab for review, preserving its writer session, or opens one when needed. A queued capture stays on this browser and is not reported as saved until a private-source draft receipt is confirmed.

For a contact’s visible profile photo, open that person’s profile in Dia and choose **Save contact photo**. This retains the source and asks Worldview to save the actual image for an existing contact only when the saved profile URL and annotated person name match exactly. It does not start reading tracking, send your unfinished comment, create a new person, or replace an existing photo. A confirmed save names the contact; an existing photo, unmatched contact, unavailable image, or queued request has a distinct status. A queued request is not a saved photo. For a profile with no named visible photo, use a local image upload in Worldview.

On a Folk contact group, use **Capture visible Folk photos** once, or explicitly choose **Follow visible Folk photos** and scroll through the group. The PH badge marks that chosen group. While it is visible and focused, changes to rendered rows queue new photos at most once per row; each batch holds at most 50 rows. Stop, navigation and browser restart end following. A full queue or extraction error also stops it; retry pending captures and explicitly follow again. Only visible names, nearby links and bounded UUID identity attributes are captured. Folk data is retained privately in People; it never enters the article archive, reading progress or knowledge sources. Ordinary article capture is disabled on Folk. Photos require an unambiguous rendered person link in the same Folk workspace and group, matching image/name, imported Folk ID and group membership. A diagnostic receipt means no contact picture changed. It never matches by name alone or replaces an existing photo.

Stop following through the popup. Navigation and browser restart also stop following. This extension has no history permission, no all-sites permission and no automatic content-script injection. The localhost host permissions allow the extension service worker to contact the fixed local endpoint; the page cannot choose a server URL.

Inside Connection settings on Folk’s Search list, **Inspect visible Folk Search photos** retains at most 50 visible image rows, visible names/emails and avatar labels as a private CRM diagnostic. Search identity is not yet verified: this action never changes contacts, companies or pictures, even if a visible link or UUID is present. It does not follow the list or add it to Knowledge or Reading.

**Save matched Search photos** is a separate explicit action. Worldview resolves the person locally only when the visible email belongs uniquely to an active imported person in the proven Folk account, the display name and primary avatar label agree, and the portrait is fully loaded. Shared emails, company logos, ambiguous names and unbound accounts are skipped. Existing pictures stay intact. **Follow matched Search photos** applies those same checks only to newly visible rows on the chosen Search page; it uses the PH badge, bounded outbox and Stop/navigation/restart rules described above.

If Worldview is offline, captures are kept in a bounded local outbox. The popup shows capture titles, delivery status, and the last failure. Reopen it and use Retry pending captures. You can remove one permanently invalid pending capture to deliver the rest. A queued message is not confirmation that the app received it. Discarding or disconnecting requires confirmation and deletes pending unsent captures. Follow state is session-only; pending captures and pairing survive browser restarts. Revocation in Worldview invalidates the token immediately. Pairings expire after 90 days.

Ordinary article captures contain extracted text and URL provenance, plus bounded profile-photo/link references. Explicit **Save profile or company** captures additionally retain a safe HTML snapshot of the loaded readable primary content. This strips scripts, interactive forms, embeds and unrelated sidebars; it is not an executable or pixel-identical copy of the entire site. Neither capture includes screenshots, cookies, form input, browser credentials or browsing history. Worldview downloads an approved contact photo into local original storage; displaying it later does not depend on the remote URL. Restrictive pages, PDFs, iframes and paywalls can prevent extraction. Progress measures scroll and approximate visible/focused dwell; it does not prove comprehension. A last few seconds of progress may be lost if the browser or page is abruptly terminated. Never use this on a page you do not intend to save.

See docs/BROWSER-READING.md in the Worldview repository for architecture, security boundaries, HTTP verification and limitations. Firefox is not supported by this build.
