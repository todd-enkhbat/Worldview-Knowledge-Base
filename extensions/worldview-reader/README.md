# Worldview Reader

Load this directory as an unpacked Manifest V3 extension in Dia, Chrome or Edge. No build or dependency install is required. The downloaded ZIP contains the same files in its WorldviewReader folder. Version 0.7.0 uses active-tab, scripting, storage and local-service permissions. A browser alarm retries queued deliveries while the browser is running.

1. Open your local Worldview workspace. The usual port is 5173. If Sources → Desktop shows another port, enter that number under Connection settings in the extension before pairing.
2. Open chrome://extensions (or edge://extensions), turn on Developer mode, click Load unpacked, and choose this folder.
3. Open the extension popup and click Connect to Worldview. In the local app’s Browser reader panel, approve the browser request you just made.
4. Reopen the extension popup to finish connecting automatically. No ID or token copying is needed. The token is saved only in this browser’s trusted extension storage; content scripts never receive it. Requests expire after five minutes; pairings last 90 days. The advanced token flow remains available as a fallback.
5. On an ordinary article page, explicitly choose Save and follow this article. A blue ON badge identifies the selected tab. Select text and reopen the popup to save it with an optional comment.

Open the popup on a personal profile or company website to preview its name, headline, current organizations, schools and location. Select a group, then click **Add to Worldview** or **Add to [group]**. Worldview saves the visible details and attempts to retain the subject’s named portrait or logo locally. If the same source is already saved, you can add the existing record to another group. Ambiguous matches open a review. **More capture options → Review profile fields in People** also lets you select individual fields before saving.

On LinkedIn, open the main profile. Previewing it keeps your place. When you choose Add or review the fields, Reader loads the Experience section and, when LinkedIn offers it, the same person’s full Experience page. It collects the roles LinkedIn displays, including dates, descriptions and linked organizations, and returns to the profile. In People, open Details to see the work history and follow an employer into Companies. Worldview looks up missing company information from identifiable public sources. On websites it recognizes a primary Person or Organization in JSON-LD, named personal pages with identifying profile metadata or a named portrait plus declared social links, and company homepages with an explicitly branded logo. Related people, forms and unrelated schema entities are excluded. The reader stores a readable source snapshot for provenance. Opening the popup previews the contact locally. Clicking Add sends the snapshot to your paired Worldview workspace.

For a contact’s visible profile photo, open that person’s profile in Dia and choose **More capture options → Save contact photo only**. This retains the source and asks Worldview to save the actual image for an existing contact only when the saved profile URL and annotated person name match exactly. It does not start reading tracking, send your unfinished comment, create a new person, or replace an existing photo. A confirmed save names the contact; an existing photo, unmatched contact, unavailable image, or queued request has a distinct status. A queued request is not a saved photo. For a profile with no named visible photo, use a local image upload in Worldview.

On a Folk contact group, use **Capture visible Folk photos** once, or explicitly choose **Follow visible Folk photos** and scroll through the group. The PH badge marks that chosen group. While it is visible and focused, changes to rendered rows queue new photos at most once per row; each batch holds at most 50 rows. Stop, navigation and browser restart end following. A full queue or extraction error also stops it; retry pending captures and explicitly follow again. Only visible names, nearby links and bounded UUID identity attributes are captured. Folk data is retained privately in People; it never enters the article archive, reading progress or knowledge sources. Ordinary article capture is disabled on Folk. Photos require an unambiguous rendered person link in the same Folk workspace and group, matching image/name, imported Folk ID and group membership. A diagnostic receipt means no contact picture changed. It never matches by name alone or replaces an existing photo.

Stop following through the popup. Navigation and browser restart also stop following. This extension has no history permission, no all-sites permission and no automatic content-script injection. The localhost host permissions allow the extension service worker to contact the paired local port; the page cannot choose a server URL.

Inside Connection settings on Folk’s Search list, **Inspect visible Folk Search photos** retains at most 50 visible image rows, visible names/emails and avatar labels as a private CRM diagnostic. Search identity is not yet verified: this action never changes contacts, companies or pictures, even if a visible link or UUID is present. It does not follow the list or add it to Knowledge or Reading.

**Save matched Search photos** is a separate explicit action. Worldview resolves the person locally only when the visible email belongs uniquely to an active imported person in the proven Folk account, the display name and primary avatar label agree, and the portrait is fully loaded. Shared emails, company logos, ambiguous names and unbound accounts are skipped. Existing pictures stay intact. **Follow matched Search photos** applies those same checks only to newly visible rows on the chosen Search page; it uses the PH badge, bounded outbox and Stop/navigation/restart rules described above.

If Worldview is offline, captures are kept in a bounded local outbox. The popup shows capture titles, delivery status, and the last failure. Temporary connection failures retry automatically about once a minute while the browser runs. You can also choose Retry pending captures. You can remove one permanently invalid pending capture to deliver the rest. A queued message is not confirmation that the app received it. Discarding or disconnecting requires confirmation and deletes pending unsent captures. Follow state is session-only; pending captures and pairing survive browser restarts. Revocation in Worldview invalidates the token immediately. Pairings expire after 90 days.

Ordinary article captures contain extracted text and URL provenance, plus bounded profile-photo/link references. Explicit CRM profile captures additionally retain a safe HTML snapshot of the loaded readable primary content. This strips scripts, interactive forms, embeds and unrelated sidebars; it is not an executable or pixel-identical copy of the entire site. Neither capture includes screenshots, cookies, form input, browser credentials or browsing history. Worldview downloads an approved contact photo into local original storage; displaying it later does not depend on the remote URL. Restrictive pages, PDFs, iframes and paywalls can prevent extraction. Progress measures scroll and approximate visible/focused dwell; it does not prove comprehension. A last few seconds of progress may be lost if the browser or page is abruptly terminated. Never use this on a page you do not intend to save.

See docs/BROWSER-READING.md in the Worldview repository for architecture, security boundaries, HTTP verification and limitations. Firefox is not supported by this build.
